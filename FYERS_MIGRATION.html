1. Why the SDKs could not coexist

fyers-apiv3 pins exact versions of two HTTP libraries that growwapi needs newer versions of, so pip cannot satisfy both:

Packagegrowwapi 1.5.0 needsfyers-apiv3 pins
aiohttp>=3.11.18,<4==3.9.3
requests>=2.32.3,<3==2.31.0

Fix: uninstall growwapi and drop it (and pyotp, only used for Groww's TOTP login) from requirements.txt. pip check is clean afterwards and discord.py 2.6.4 works with aiohttp 3.9.3.

2. What the bot did with the Groww API

Every Groww call went through api_utils/groww_api_handlers.py (now deleted) and utils/token_generator.py. These are all the actions the bot performed:

The bot never placed, modified or cancelled orders through Groww. Everything was read-only.

3. Groww vs Fyers, action by action

AspectGroww (before)Fyers (after)

ClientGrowwAPI(access_token)fyersModel.FyersModel(client_id=..., token=access_token). Sends header Authorization: app_id:access_token
Symbol formatSeparate exchange + segment + symbol: NSE, CASH, NSE-NIFTYOne string with exchange and series built in: NSE:NIFTY50-INDEX, NSE:SBIN-EQ
Historical candlesget_historical_candles(...); times as "YYYY-mm-dd HH:MM:SS"; interval "1hour"FYERS.history({symbol, resolution, date_format, range_from, range_to, cont_flag}); epoch seconds; resolution "60"
History window limit150 days per request was enough for the strategy100 days per request for minute resolutions, 366 for 1D/1W/1M. The handler now splits the range into chunks and removes duplicate candles
Candle shape[ts, o, h, l, c, v], close at index 4[epoch, o, h, l, c, v], close at index 4 (unchanged)
Live quoteget_quote(exchange, segment, trading_symbol)["last_price"]FYERS.quotes({"symbols": sym})["d"][0]["v"]["lp"]; up to 50 symbols per call

Portfolio LTPOne get_quote per holding, with a 1 s sleep between callsUses ltp already in the holdings response, so no extra calls
Error reportingSDK raised exceptionsBody has {"s": "error", "code": -N, "message": ...}, often without an exception. The handler checks s == "ok"
Rate limitsHit intermittently, which led to the 0.5 s submit stagger10/s · 200/min · 100k/day (Standard). Going over the per-minute limit more than 3× in a day blocks the user for the rest of the day

Credentials file~/.growwSecretKey, positional lines: api_key, totp_secret, access_token~/.fyersSecretKey.json (mode 600): client_id, secret_key, redirect_uri, pin, access_token, refresh_token

4. Authentication: the biggest difference

StepGrowwFyers
Initial loginNone needed: API key + TOTP secret were enoughpython generate_token.py: open the printed login URL, log in, paste the redirect URL back. Exchanges auth_code + appIdHash (SHA-256 of app_id:app_secret) for access and refresh tokens. A random state is sent and checked on return
Daily 07:00 jobGrowwAPI.get_access_token(api_key, totp)POST /api/v3/validate-refresh-token with refresh_token + PIN
Daily 07:01 jobrefresh_groww_credentials()refresh_fyers_credentials() rebuilds FyersModel
Manual effortNoneLog in again every 15 days, when the refresh token expires. The bot posts a Discord LOGS alert when the refresh fails
Open risk: refresh tokens may already be discontinued. The Fyers docs (API-FYERS.HTML) say "Refresh token will be discontinued from 1st April" and link to a "Regulatory Changes (April 2026)" page, which is not in the saved file and returns 404 from outside the docs site. If refresh tokens are gone, the 07:00 job fails every day and a manual login is needed daily. The fallback is a daily login, either manual or automated through Fyers' unofficial TOTP endpoints. Check this on the live docs before relying on the daily job.

7. Not migrated yet

These still hold Groww-shaped data. They don't call the Groww API, so nothing breaks at runtime:

  • sql/eq.sql, sql/idx.sql, sql/watchlist.sql: groww_symbol column. sql/portfolio.sql: groww_locked_quantity. Renaming these needs a migration on the prod database.
  • instrument/*.csv: Groww instrument dumps. They could be replaced by the Fyers symbol master.
  • trade_utils/save_instruments.py, utils/csv_helper.py, trade_utils/watchlist.py: read and write the columns above. The instrument sync is not scheduled in main.py.
SDK support note. Fyers documents the Python SDK as supporting Python 3.8–3.12. The venv runs Python 3.14.7. It installs and imports, and the smoke tests pass, but this combination is not officially supported.

8. Setup after merging

  1. pip uninstall -y growwapi pyotp && pip install -r requirements.txt
  2. Create an app in the Fyers API dashboard with only the permissions needed (Basic, Transactions Info, Market Data; no Order Placement).
  3. Create ~/.fyersSecretKey.json: 
    {"client_id": "XXXXXXXX-100", "secret_key": "...", "redirect_uri": "https://...", "pin": "1234"}
  4. Run python generate_token.py and complete the browser login.
  5. Start the bot: python main.py. Confirm the 07:00 "Fyers Access Token generated..." message in the Discord LOGS channel the next morning.

Full Fyers reference: FYERS_API_REFERENCE.html
