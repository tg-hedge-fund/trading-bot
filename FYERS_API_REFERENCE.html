Fyers API v3: quick reference

Condensed from the official docs (API-FYERS.HTML, change log up to 01 Oct 2026) for use with this bot. used marks what the bot calls today.

Request & response structure

Every authenticated request sends the app id and access token in one header:

Authorization: <app_id>:<access_token>        e.g.  Authorization: aaa-99:bbb
OutcomescodemessageExtra
Success"ok"200""Endpoint-specific key(s), e.g. candles, d, holdings
Failure"error"negative interror textHTTP status set as in the table below
Errors often come back as a normal JSON body, not an SDK exception. Always check response["s"] == "ok". fyers_api_handlers._check_response does this.

Rate limits

WindowStandard (free)Prime
Per second1010
Per minute200600
Per day100,000200,000
User blocking: going over the per-minute limit more than 3 times in a day blocks the user for the rest of the day. Order APIs also return HTTP 429 when throttled. WebSocket: up to 5,000 subscriptions and only one connection instance at a time.

Bot budget: a Golden Cross run makes 13 indices × (2 history chunks + 1 quote) = 39 calls. The 0.5 s stagger between submissions and 3 workers keep this well under 10 per second.

Login flow (user apps)

  1. Get an auth code. GET /api/v3/generate-authcode?client_id=<APP_ID>&redirect_uri=<URI>&response_type=code&state=<random>. The user logs in, and Fyers redirects to redirect_uri?auth_code=...&state=.... Check that state matches what you sent.
  2. Exchange it for tokens. POST /api/v3/validate-authcode
{ "grant_type": "authorization_code",
  "appIdHash":  sha256("<app_id>:<app_secret>").hexdigest(),
  "code":       "<auth_code>" }
→ { "s": "ok", "code": 200, "access_token": "...", "refresh_token": "..." }

SDK equivalent (what utils/token_generator.login_with_auth_code does):

session = fyersModel.SessionModel(client_id=APP_ID, secret_key=SECRET, redirect_uri=URI,
                                  response_type="code", grant_type="authorization_code", state=state)
url = session.generate_authcode()      # open in browser
session.set_token(auth_code)
tokens = session.generate_token()

Best practices: never share app_secret or access_token; don't grant trading permission unless needed; use a redirect_uri you control; always send and check a random state.

Refresh token

POST /api/v3/validate-refresh-token. The refresh token is valid for 15 days.

{ "grant_type": "refresh_token", "appIdHash": "...", "refresh_token": "...", "pin": "<user PIN>" }
→ { "s": "ok", "code": 200, "access_token": "..." }
Deprecation warning: the docs say "Refresh token will be discontinued from 1st April", with a separate "Regulatory Changes (April 2026)" page that applies SEBI's retail-algo rules. If it has already been switched off, the bot's 07:00 refresh will fail every day and a fresh login (step 1) will be needed daily. Check the live regulatory page.

History used

fyers.history(data={
    "symbol": "NSE:NIFTY50-INDEX",
    "resolution": "60",          # see table
    "date_format": "0",          # 0 = epoch seconds, 1 = yyyy-mm-dd
    "range_from": "1747000000",
    "range_to":   "1760000000",
    "cont_flag": "1",            # continuous data for futures/options
    # "oi_flag": "1",            # include open interest
})
→ {"s": "ok", "candles": [[epoch, open, high, low, close, volume], ...]}
Resolution valuesMax range per request
5S 10S 15S 30S 45S (seconds)Last 30 trading days only
1 2 3 5 10 15 20 30 45 60 120 180 240 (minutes)100 days; data from 3 Jul 2017

Partial candles: to get only completed candles, set range_to to now minus one resolution period. The bot uses now − 1 h for 60-minute candles. There is no daily download limit on history.

Bot wrapper: get_historical_data(symbol, resolution, range_from: datetime, range_to: datetime) splits ranges longer than the limit into chunks, removes duplicate candles by timestamp, and returns {"candles": [...]} or None.

Placing orders (for later)

fyers.place_order(data={
    "symbol": "NSE:SBIN-EQ", "qty": 1,
    "type": 2,                 # 1 limit, 2 market, 3 SL-M, 4 SL-L
    "side": 1,                 # 1 buy, -1 sell
    "productType": "CNC",      # CNC | INTRADAY | MARGIN | MTF
    "limitPrice": 0, "stopPrice": 0,
    "validity": "DAY",         # DAY | IOC
    "disclosedQty": 0, "offlineOrder": False,   # True = AMO
    "stopLoss": 0, "takeProfit": 0,
    "orderTag": "tghf", "isSliceOrder": False,
})
  • Cover Order (CO) and Bracket Order (BO) are deprecated and get rejected. Use stopLoss/takeProfit on a normal order instead.
  • SL-M / SL-L: stopPrice must not be above LTP for a sell or below LTP for a buy. For SL-L buys, stopPrice must be below limitPrice.
  • Derivative quantities must be multiples of the lot size. isSliceOrder splits orders above the freeze quantity.
  • SEBI retail-algo rules (from April 2026) add order-type restrictions and app activation requirements. Check the regulatory page first.

Fytoken = exchange (2 digits) + segment (2 digits) + expiry YYMMDD (6 digits) + exchange token (2–6 digits). Example: 101000000016921 is NSE · CM · no expiry · token 16921.

WebSocket

  • Data socket (fyers_apiv3.FyersWebsocket.data_ws): symbol, index and depth updates, plus a lite mode with LTP only. Up to 5,000 subscriptions; one instance at a time; runs on its own thread.
  • Order socket (order_ws): order, trade, position and general updates. Needed to see results of async orders.
  • TBT socket (tbt_ws): tick-by-tick, 50-level depth. NSE F&O and equity.
  • Set reconnect=True (max 50 retries via reconnect_retry). To change symbols, unsubscribe and resubscribe. write_to_file only works without callbacks.
